# RISK-ERA Demo Script

## 2–3 Minute Demonstration

### 0:00 — Problem
Financial fraud detection requires both automated response and thorough investigation. Analysts need a system that combines rule-based anomaly detection with AI-powered evidence gathering — without exposing raw data or granting the LLM direct database access.

### 0:15 — Dashboard
The analyst logs in via JWT authentication and lands on the dashboard. Metrics show open, in-progress, and escalated case counts. A list of recent cases is displayed with status badges (OPEN, IN_PROGRESS, ESCALATED). The analyst selects a suspicious case from the list.

### 0:30 — Open Suspicious Case
The case investigation page loads, displaying:
- Transaction amount (synthetic; e.g., $15,200) with merchant and location flags
- Risk score from the rule engine (`block_high_amount`: amount > 10,000 → BLOCK)
- Initial findings from the rule engine
- Evidence status: IDs validated against schema; marked valid/missing/referenced

The analyst reviews the transaction details and risk score, confirming this warrants investigation.

### 0:50 — Show Transaction/Risk/Evidence
The page shows:
- **Transaction**: amount, merchant, location (all synthetic; no real PII)
- **Risk score**: derived from DSL rules (`amount > 10000` triggers BLOCK)
- **Evidence**: evidence IDs with status labels — some valid, some missing, some referencing external data
- The analyst can see which evidence is grounded and which requires attention

### 1:05 — Run Nemotron Investigation
The analyst clicks "Run Investigation." The system:
1. Executes controlled tool calls to retrieve sanitized evidence related to the transaction
2. Calls NVIDIA Nemotin API: `https://integrate.api.nvidia.com/v1` with model `nvidia/nemotron-3.5-lightning-30b-a3b`
3. Validates evidence IDs against the schema before the model generates a response
4. Returns an InvestigationResult with findings, recommendation, and confidence score

No raw database rows are sent to the LLM. Only schema-validated evidence summaries are provided.

### 1:30 — Show Tools/Evidence-Grounded Findings
The investigation result displays:
- **Recommendation**: ACCEPT / MODIFY / REJECT (generated by Nemotron based on evidence)
- **Confidence score**: 0.0 – 1.0 (probability the recommendation is correct)
- **Findings**: Narrative explanation of the model's analysis, referencing specific evidence IDs
- **Evidence IDs**: List of validated evidence IDs that supported the recommendation
- The analyst can see which evidence IDs the model referenced and assess whether the reasoning is sound.

### 1:50 — Show Recommendation
The recommendation is displayed clearly:
- If ACCEPT: the case can be closed or escalated
- If MODIFY: the analyst can adjust findings or add notes
- If REJECT: the analyst provides a reason for rejection
- The confidence score quantifies the model's certainty

### 2:05 — Submit Analyst Feedback
The analyst submits feedback:
- Select ACCEPT/MODIFY/REJECT
- Optional: add a reason text field
- `POST /api/v1/feedback/` sends the feedback to the backend
- The result is persisted to PostgreSQL
- An audit event (`EVIDENCE_ADDED` or feedback event) is recorded with the hash chain

### 2:20 — Show Audit Trail
The analyst views the audit page:
- All events from investigation start through feedback are listed
- "Verify Chain" button triggers `audit_service.verify_chain()` — SHA-256 hash-chain integrity validation
- Any modification to any event would invalidate the entire chain, demonstrating tamper-evidence
- The audit trail proves: case opened → investigation run → result received → feedback submitted

### 2:35 — Closing Architecture Explanation
Key architecture points:
- **Controlled tools**: The investigator executes predefined sanitized tools; no direct DB access
- **Evidence grounding**: IDs are validated against a schema before the model sees them
- **JWT/RBAC**: Authentication via `Authorization: Bearer`; ANALYST/ADMIN roles with 30+ permissions
- **Audit hash chain**: SHA-256 linked events; tamper-evident logging
- **No secrets in frontend**: No NVIDIA API key, no database credentials, no JWT secrets in the browser
- **Synthetic data**: No real customer PII at any point
